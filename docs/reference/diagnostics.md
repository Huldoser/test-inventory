# Diagnostics

A diagnostic is part of the output, not a failure: the scan always finishes and exits with 0. Its `level` is `error`
when tests may be missing from the output, and `warning` when a value is missing or approximate.

## Files and imports

| Code                            | Level                            | When                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `read-error`                    | error                            | A test file or a folder could not be read, or a test file is a link to a file that does not exist.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `parse-error`                   | error                            | The file has a syntax error, or brackets nested more than 500 deep, which would crash the parser, or code the parser can't hand over, such as a JSX name written as a Unicode escape; such a file is not parsed at all. When the parser recovers from a syntax error, the tests it read are kept.                                                                                                                                                                                                                                                                                                                                              |
| `internal-error`                | error                            | Reading the file or a config failed unexpectedly. Please report it with the file if you can. The scan goes on with the next file, and reads none of the config's settings.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `framework-mismatch`            | error                            | The file imports another framework, such as Vitest in a Playwright scan or `@jest/globals` in a Vitest scan.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `unresolved-test-import`        | error                            | A call shaped like a test, outside any test or hook body, uses a name imported from a module that could not be followed. Files are followed through re-exports and `extend` chains; the message says where the chain ends: a missing or broken file, an installed package, or a file that doesn't export a test object. The name reads like a test function, as `test` or `checkoutTest` do, or is followed by a member such as `.describe`.                                                                                                                                                                                                   |
| `invalid-import`                | error                            | Vitest imported in a way it does not support: a default import, or `require('vitest')`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `no-files-matched`              | warning                          | No test file matches the patterns. When a pattern names a folder, the message suggests a pattern for the test files in it. The command line also says so on standard error.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `unsupported-file`              | warning                          | A file that matches the patterns is not JavaScript or TypeScript, so it is not read.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `symlink-ignored`               | warning                          | A Playwright or Jest test file is reached through a symbolic link, which these runners do not follow.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `local-test-object`             | warning                          | A variable or function named like a test object makes one in a way the scan cannot follow, as in `const it = await createTester()` or `liveBrokerTest(options)('title', fn)`. Calls on it shaped like tests are read as tests.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `globals-not-enabled`           | warning                          | A Vitest file uses `describe`, `it` or `test` without importing them, the config it uses doesn't set `test.globals` to `true`, and no tsconfig has `vitest/globals` in its types. A Jest file uses them while the config that runs it sets `injectGlobals` to `false`.                                                                                                                                                                                                                                                                                                                                                                         |
| `file-not-run`                  | warning                          | A file the patterns match has tests, but no config in its folder or above runs it, so the runner doesn't collect them. The message names the nearest config; see [configs](/reference/output#configs).                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `forbidden-only`                | error, warning under a condition | Playwright's `forbidOnly` is on in the config, so a `.only` makes the run fail before any test runs. When `forbidOnly` depends on a condition, as in `!!process.env.CI`, it is a warning that quotes it.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `dependency-not-followed`       | warning                          | Something a test runs can't be followed: a local file that is missing or doesn't parse, `import()` or `require()` with a path worked out at run time, `import.meta.glob()`, a value imported from a module that only a declaration file describes, a setup file the config names in a way the scan can't work out or that doesn't exist, a config that puts snapshots elsewhere than the runner's default, or a `toMatchFileSnapshot()` path worked out at run time or absolute. Tests that reach it have `hasUnfollowedDependencies`, and a change there doesn't change their `dependencyHash`. Reported once per place, where it is written. |
| `unknown-framework-version`     | warning                          | The framework version could not be read from the project; the newest rules apply.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `approximate-framework-version` | warning                          | Only a version range was found, such as `^4.0.0` in `package.json`; the rules of the newest release in that major apply.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `unsupported-framework-version` | warning                          | The project uses a version older than Playwright 1.42, Vitest 3.0 or Jest 29.0.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

## Declarations

| Code                       | Level                        | When                                                                                                                                                                                                                                                                                                                           |
| -------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `invalid-chain`            | error                        | A chain the framework does not have, such as `test.only.skip` in Playwright or `test.only.concurrent` in Jest, or one that needs a newer version. Also Jest's `test.todo()` with more than a title.                                                                                                                            |
| `test-without-body`        | error                        | Playwright `test('title')` without a function, which makes Playwright fail to load the file and run no tests at all, or Jest `test('title')` or `describe('title')` without one, which makes Jest fail the file.                                                                                                               |
| `describe-not-called`      | error                        | Vitest `describe(fn)` without a title. Vitest never calls the function.                                                                                                                                                                                                                                                        |
| `async-describe`           | error                        | A Playwright describe callback that awaits. Playwright does not wait for it: tests declared after the first `await` end up in the describe around it, or are not collected at all. A Jest describe callback that is async or returns a promise, which makes Jest fail the file.                                                |
| `describe-throws`          | error                        | A Jest describe that throws while Jest collects it: its callback returns a value, as `() => symbols.map(...)` does, or its `.each` table is empty, isn't a table, or has no function. Jest fails the file.                                                                                                                     |
| `tag-without-at`           | error                        | A Playwright tag that does not start with `@`, which makes Playwright fail to load the file and run no tests at all.                                                                                                                                                                                                           |
| `removed-api`              | error                        | An API the framework version removed: Vitest 5 `sequential` and `bench`, `vi.mock`, `vi.unmock` or `vi.hoisted` below the top level of the file from Vitest 5, or options as the third argument from Vitest 4. Vitest fails the file.                                                                                          |
| `duplicate-id`             | error                        | Two records in a file have the same id. Ids include a position among equal titles, so only a hash collision causes this.                                                                                                                                                                                                       |
| `duplicate-title`          | warning, error in Playwright | Playwright: two tests in the file have the same title path, without anonymous describes, or a test in a loop has the same title path on each pass, so Playwright fails to load the file and runs no tests at all. Vitest and Jest: two tests in the same describe have the same title.                                         |
| `state-in-helper`          | warning                      | A `test.skip()`, `test.fixme()`, `test.fail()` or `describe.configure()` is in a function that the file exports or never calls, so it is not applied to any record. Also given when a call in a test or hook reaches helpers more than 10,000 times, counting the calls inside them; the states set past that are not applied. |
| `skip-without-body`        | warning                      | Playwright `test.skip('title')` without a function: Playwright reads the title as a condition and skips every test in the scope.                                                                                                                                                                                               |
| `nested-test`              | warning                      | A test or describe declared inside a test body or hook. The runner does not collect it, so it is not listed.                                                                                                                                                                                                                   |
| `only-in-skipped-describe` | warning                      | A test with `.only` inside a skipped describe. It is still skipped.                                                                                                                                                                                                                                                            |

| `test-in-loop`                 | warning                                   | The test is declared in a loop whose values the scan can't work out. | `test-in-function`             | warning                                   | The test is declared in a function the scan can't place: nothing in the file calls it by name, the file only exports it, or it is called only from tests or hooks. | `empty-title`                  | warning                                   | A test or describe is titled with an empty string. The runners allow it, but reports and filters can't tell it apart.                                                                                                                                                                                                                                                                                                                                                                                                       |
| `bench-outside-benchmark-file` | warning                                   | A test uses Vitest 5's `bench` fixture outside a benchmark file such as `*.bench.ts`, where Vitest fails the test. It still has `isBenchmark`.                                                                                                                                                                                                                                                                                                                                                                              |
| `config-may-change-state`      | warning                                   | A Vitest file uses tags, and the scan can't work out the tags the Vitest config defines, which can skip tests or change how they run.                                                                                                                                                                                                                                                                                                                                                                                       |
| `undefined-tag`                | error, warning in a function or condition | A Vitest file uses a tag the config doesn't define, and `strictTags` is on, as it is unless the config turns it off. Vitest fails the file while it loads, at the first such tag it meets: the file's `@module-tag` comments first, then the describes' tags, then the tests'. Reported at the first use of each such tag. A use in a function or under a condition fails the file only if that code runs, so it is a warning, and the file's tests keep their state.                                                       |
| `config-value-unknown`         | warning                                   | The scan reads a setting of the config that it can't work out without running the config, such as `globals: process.env.CI === 'true'`, or it can't read the config at all. Also a Jest `preset` the scan doesn't read that may choose the test files, and a Jest config Jest refuses: `testMatch` with `testRegex`, a `testRegex` or ignore pattern that isn't a regular expression, or two configs in one folder. The message names the setting and what the scan does instead; see [configs](/reference/output#configs). |

## Files the runner refuses to load

Some problems make the runner fail while it loads a file:

- Playwright: `test-without-body`, `tag-without-at`, `invalid-chain` and `duplicate-title`. Playwright then stops
  before it runs any test, in this file or any other.
- Vitest: `invalid-chain`, `removed-api` and `undefined-tag`. Vitest reports the file as failed and runs none of its tests; other
  files still run.
- Jest: `invalid-chain`, `test-without-body`, `async-describe` and `describe-throws`. Jest reports the file as failed and runs none of its
  tests; other files still run.

Every test in such a file gets `state: "notLoaded"`, with `stateSource: "file"` and `stateLine` at the first of these
problems. These tests are counted in `notLoadedCount`, not in `activeCount`. Everything else about them is kept, so
the records show what the file declares once the problem is fixed. A refused call written like a declaration, such as
`test.only.skip('title', fn)` or `describe.sequential('title', fn)` in Vitest 5, is listed too, as a plain test or
describe without the part that fails, so its tests are `notLoaded` rather than missing. Tests in other files keep
their states, even though Playwright runs none of them: the records describe the code, and the diagnostic points at
the file to fix.

Only code that runs while the file loads counts. An `invalid-chain` inside a test, hook or helper body, such as
`test.step.skip()` before Playwright 1.50 or `test.slow()` in Vitest, runs later and fails only the test that reaches
it, so the file loads. A refused call reached only under a condition, as in `if (process.env.LEGACY) test.only.skip(...)`,
is reported, but its file's tests keep their states, since the file loads unless the condition holds.
